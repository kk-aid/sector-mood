# 업종 × 요일 심리 지도 (미국·한국·일본)

미국·한국·일본 상장 종목을 FactSet 20개 섹터로 묶어, 매일 **시장 대비 등락**과 **상대 거래**를 함께 보고 업종 심리를 6칸으로 분류하는 트래커임.
GitHub Actions가 평일 두 번 데이터를 수집·계산하고, GitHub Pages가 화면을 보여줌. 서버 비용 0원.

| 시장 | 실행 시각 (한국) | 유니버스 | 시총 하한 |
|---|---|---|---|
| 미국 | 07:30 (전일 장) | NYSE·NASDAQ·AMEX 보통주+ADR | 10억 달러 |
| 한국 | 16:40 (당일 장) | 코스피·코스닥 보통주 | 3,000억 원 |
| 일본 | 16:40 (당일 장) | 도쿄증권거래소 보통주 | 1,000억 엔 |

위쪽 단위(섹터/산업)·가중·등락 기준·거래 기준 선택은 모든 보기에 공통으로 적용됨. 산업 단위는 섹터 필터와 최소 종목 수(기본 5)로 걸러 볼 수 있음.

시총 하한은 `pipeline/config.py` 의 `MARKETS` 에서 바꿀 수 있음. 바꾼 뒤에는 Run workflow 에서 **이번 달 유니버스를 새로 구성** 을 체크해 실행.

## 1. 설치 (최초 1회, 약 10분)

1. GitHub에서 새 저장소 생성 (예: `sector-mood`). **Public**이어야 무료 플랜에서 Pages 사용 가능함.
2. 이 폴더 내용을 그대로 올림.
   ```bash
   cd sector-mood
   git init && git add . && git commit -m "init"
   git branch -M main
   git remote add origin https://github.com/<아이디>/sector-mood.git
   git push -u origin main
   ```
3. 저장소 **Settings → Actions → General → Workflow permissions** 에서 **Read and write permissions** 선택 후 저장.
4. **Actions 탭 → update-sector-mood → Run workflow** 로 첫 실행. 첫 실행은 자동으로 26주 백필을 하므로 10~20분 걸림.
5. **Settings → Pages → Build and deployment**: Source = *Deploy from a branch*, Branch = `main`, 폴더 = `/docs` 선택 후 저장.
6. 1~2분 뒤 `https://<아이디>.github.io/sector-mood/` 에서 확인.

이후에는 평일마다 자동 갱신됨. 수동 갱신은 Actions 탭에서 Run workflow.

## 1-1. 텔레그램 아침 알림 (선택)

평일 아침 갱신이 끝나면 전일 미국장 업종 심리 요약이 텔레그램으로 옴. 갱신이 실패하면 실패 알림이 옴.

1. 텔레그램에서 `@BotFather` → `/newbot` → 이름 입력 → **토큰** 받음 (`123456:ABC...` 형태)
2. 만든 봇과 대화창을 열고 아무 메시지나 보냄
3. 브라우저에서 `https://api.telegram.org/bot<토큰>/getUpdates` 접속 → `"chat":{"id":숫자` 의 숫자가 **chat id**
   - 채널로 받으려면 봇을 채널 관리자로 추가하고 chat id 에 `@채널아이디` 입력
4. 저장소 **Settings → Secrets and variables → Actions → New repository secret** 으로 두 개 등록
   - `TELEGRAM_BOT_TOKEN` = 토큰
   - `TELEGRAM_CHAT_ID` = chat id
5. 테스트: Actions → Run workflow → **텔레그램 알림 보내기** 체크 후 실행

미국은 아침 7시 40분경, 한국·일본은 오후 4시 50분경 시장별로 따로 옴. 판정 기준은 `pipeline/config.py` 의 `NOTIFY_*` 값임(기본: 시총가중·고정 %p·거래대금). 메시지 미리보기는 `python -m pipeline.notify --market kr --dry-run`.

## 1-2. 신고가 알림 (한국·미국·일본)

장 마감 후 **역대 신고가(ATH)** 와 **52주 신고가** 종목을 섹터별로 묶어 텔레그램으로 보냄. 1-1 에서 등록한 봇·시크릿을 그대로 씀.

| 시장 | 실행 시각 (한국) | 기본 필터 |
|---|---|---|
| 한국 | 16:20 (당일 장) | 시총·거래대금 제한 없음, 시총 500억 미만은 `소형주·시총500억↓` 로 묶음 |
| 일본 | 16:20 (당일 장) | 시총 100억 엔·거래대금 1억 엔 이상 |
| 미국 | 07:20 (전일 장) | 시총 3억 달러·거래대금 500만 달러 이상 |

**판정**: ① 상승 마감 + 종가 > 시가 (우선주·스팩 제외) ② 당일 고가 ≥ 역대 최고가 / 52주 최고가. 상승률 순위 제한은 기본으로 없음(`NEWHIGH[시장]["top_n"]` 에 숫자를 넣으면 상위 N 안에서만 찾음). 52주 목록은 역대 신고가 종목을 뺀 나머지임. 고가는 TradingView 기준(분할·무상증자 반영)이라 증자 후 신고가가 빠지지 않음.

**섹터 라벨**: `data/newhigh/labels.csv` 에 있는 종목은 그 라벨, 없으면 FactSet 산업명(한국어). 테마 라벨(예: 대북, 정치)을 붙이고 싶으면 이 파일에 `market,code,label` 한 줄 추가하면 됨.

**기록**: `data/newhigh/<시장>/YYYY-MM.csv` 에 매일 누적. 휴장일에는 직전과 결과가 같아 자동으로 건너뜀.

- 기준 바꾸기: `pipeline/config.py` 의 `NEWHIGH` (상위 몇 위, 시총·거래대금 하한, 소형주 기준)
- 다른 채널로 받기: 시크릿 `NEWHIGH_CHAT_ID` 추가 (없으면 `TELEGRAM_CHAT_ID` 로 감)
- 미리보기: Actions → **new-highs** → Run workflow → *전송·기록 없이* 체크, 또는 `python -m pipeline.newhigh --market kr --dry-run`
- 특정 종목이 왜 빠졌는지: Run workflow 의 **check** 칸에 `KT&G,코웨이` 처럼 입력 → 로그에 종목별 포함·제외 이유와 시가·종가·고가·52주 고가 출력

**보강 (차트·재료·군집)** — 기존 메시지(라벨·기업명·등락률)는 그대로 두고 덧붙임
- 🔥 **군집**: 같은 라벨에서 당일 3종목 이상(또는 5일 누적 6종목 이상)이면 맨 위에 요약, 라벨 줄 아래에 `└ 업종:` (업종 심리 지도의 주간 상대 등락·로테이션 분면) · `└ 공시`/`└ 뉴스` 한두 줄
- 📊 **차트 이미지**: 군집 상위 3개(없으면 상승률 상위 6종목)를 1년 일봉·20/50/200일선·직전 52주 고점선·거래량으로 묶어 사진으로 전송
- 🔗 **사이트 '신고가' 탭**: 날짜별 전 종목 카드(차트·공시·뉴스·차트/네이버/공시 바로가기), 군집 표, 라벨별 신고가 추이, 신고가 이후 성과
- 재료 소스: 뉴스는 Google News RSS(최근 3일, 제목·링크만), 공시는 한국 DART(시크릿 `DART_API_KEY` 등록 시) · 미국 SEC EDGAR. 일본은 뉴스만.
- 재료는 '그날 나온 소식 목록'이지 원인 확정이 아님. 공시·뉴스가 없으면 "재료 미확인"으로 표시함.
- 보강이 실패해도 기존 신고가 메시지는 그대로 전송됨. 끄려면 `python -m pipeline.newhigh --no-enrich`.

**DART 키 등록 (한국 공시, 무료)**: opendart.fss.or.kr → 인증키 신청 → 발급된 40자리 키를 저장소 **Settings → Secrets and variables → Actions** 에 `DART_API_KEY` 로 등록. 등록 다음 실행부터 자동으로 공시가 붙음.

## 2. 구조

```

  config.py     시장 정의·기준값·시총 하한·업종 한글명
  universe.py   TradingView 스크리너로 유니버스 구성 (월 1회 고정, 실패 시 지난달 재사용, 종목명·산업명 한글)
  prices.py     yfinance 일봉 2년치 수집 (한국은 .KS 실패 시 .KQ 재시도)
  compute.py    섹터·산업 지표, 규모와 쏠림, 시총 증감 → docs/data/<시장>/weeks/YYYY-MM-DD.json
  macro.py      매크로 대시보드 (yfinance + FRED CSV, 키 불필요) → docs/data/macro.json
  weekly.py     주간 요약 (각 시장 주간 파일 + 실제 지수·ETF 종가) → docs/data/weekly/<월요일>.json
  analytics.py  주간 이력·로테이션·신호 검증·추세(이평 배열/Stage/Minervini/breadth) → history/signals/trend.json
  run.py        실행 진입점
  newhigh.py    신고가 알림 (TradingView 스크리너 조회 → 판정 → 기록 → 텔레그램)
  newhigh_enrich.py  신고가 보강 (1년 가격·차트 이미지·공시·뉴스·군집·업종 흐름·사후 성과 → 사이트 JSON)
  synthetic.py  네트워크 없이 테스트용 가짜 시장
docs/
  index.html    화면 틀·스타일
  app.js        화면 로직 (6개 보기)
  data/         계산 결과 (Actions가 매일 커밋)
data/universe/  시장별·월별 유니버스 스냅샷
data/newhigh/   신고가 섹터 라벨(labels.csv)·시장별 월간 기록
tests/          계산 검증 (손계산 대조)
```

## 3. 지표 정의

| 지표 | 정의 |
|---|---|
| 상대 등락 | 업종 수익률 − 시장 수익률 (%p). 시총가중(전일 시총) / 동일가중 선택 |
| 상대 거래대금 | (업종 당일 거래대금 ÷ 업종 직전 20일 평균) ÷ (시장 동일 비율) |
| 상대 거래량 | 종목별 (거래량 ÷ 직전 20일 평균)의 업종 평균 ÷ 시장 평균. 가격 효과 제거 버전 |
| σ | 업종 일간 상대 등락의 직전 60거래일 표준편차 (주 시작 시점 기준). 주간은 σ×√일수 |
| 상승일 거래 | 그 주 종목 거래대금 중 상승한 날에 발생한 비중 |
| 거래 몫 | 시장 전체 거래대금 중 비중 |
| 거래 배수 | 종목 주간 일평균 거래대금 ÷ 직전 20일 평균 |
| 이긴 날 | 업종이 시장보다 좋았던 날 수 |
| 시총 증감 | 주식 수 × (그 주 마지막 종가 − 직전 주 마지막 종가) |
| 규모 | 연초 첫 거래일 시총 순위로 초대형 10 / 11–100 / 101–500 / 501위 이하 구간을 나눈 절대 수익률 |
| 쏠림 | 그날 시장 거래대금 중 거래대금 상위 10종목의 몫 |
| RS 추세 (로테이션 가로) | 100 × RS ÷ 10주 평균 RS. RS = 업종 누적지수 ÷ 시장 누적지수 |
| RS 모멘텀 (로테이션 세로) | 100 + (RS 추세 − 4주 전 RS 추세) |
| 완전 정배열 | 가격 > 5 > 20 > 60 > 120 > 200일선 (주봉: 가격 > 10 > 20 > 30 > 40주선) |
| 정배열 진행 | 가운데 세 선만 정렬 (일봉 20>60>120, 주봉 20>30>40) |
| Stage | 30주선 4주 기울기 +1% 초과: 가격 위 2·아래 3 / −1% 미만: 아래 4·위 1 / 횡보: 26주 전보다 높으면 3, 아니면 1 |
| Minervini 8조건 | 가격>150·200일선, 150>200, 200일선 1개월 상승, 50>150·200, 가격>50일선, 52주 저점+30% 이상, 52주 고점−25% 이내, RS 등급 70+ |
| RS 등급 | 3·6·9·12개월 수익률 40·20·20·20 가중, 시장 유니버스 내 백분위 (0~99) |

**분류**

| | 거래 기준 이상 | 거래 기준 미만 |
|---|---|---|
| 상승 기준 이상 | 거래 몰린 상승 | 조용한 상승 |
| 그 사이 | 손바뀜 | 소강 |
| 하락 기준 이하 | 거래 몰린 하락 | 관심 이탈 |

- 기본값: 일간 ±1%p·1.1배, 주간 ±2%p·1.05배, σ 모드 ±1σ. 화면에서 바로 바꿀 수 있음(브라우저에 저장).
- ⚑ 이벤트일: 미국 3번째 금요일(옵션 만기·쿼드러플 위칭), 한국 2번째 목요일(옵션 만기·동시만기), 일본 2번째 금요일(SQ·메이저 SQ), 시장 거래대금 1.4배 이상 급증일, 0.65배 이하 저거래일.

## 4. 알려진 한계

- **데이터 소스가 비공식임.** yfinance(야후)와 TradingView 스크리너는 공식 API가 아님. 구조가 바뀌면 깨질 수 있음. 유니버스는 실패 시 지난달 파일을 재사용하고, 가격은 4회 재시도함. 깨지면 Actions 탭에 빨간 X가 뜸.
- **생존 편향이 약간 있음.** 과거 주를 백필할 때 현재 유니버스를 씀. 그 사이 상장폐지된 종목은 빠져 있음.
- 한국·일본 시장 수익률은 지수(코스피·닛케이)가 아니라 이 유니버스의 시총가중·동일가중 평균임.
- 업종 분류는 TradingView(FactSet) 기준임. GICS와 다름. 예: 애플은 전자 기술, 엔비디아도 전자 기술.
- **신호 검증은 가설 점검용임.** 2년 미만 기간, 업종 간 상관, 4주 성과의 기간 중첩(t값 부풀림), 거래비용 미반영, 생존 편향이 있음. 여러 조합을 바꿔 보다 우연히 좋아 보이는 조합을 고르는 것(데이터 마이닝)에 주의.
- 로테이션 좌표는 JdK RRG 공개 근사식이라 상용 RRG 값과 다름.
- 저장소 용량: 매일 바뀌는 JSON 이 커밋되므로 git 이력이 1년에 100~200MB 정도 늘어남. 커지면 데이터 브랜치 분리나 Pages 아티팩트 배포로 바꾸면 됨.
- GitHub 예약 실행은 몇 분~수십 분 지연될 수 있음.
- 저장소에 60일간 활동이 없으면 예약 실행이 멈춤. 매일 데이터 커밋이 생기므로 보통은 문제없음.

### 추가 RS·거래대금·R/S Flip·ETF 알림

기존 `new-highs` 알림은 변경하지 않는다. `strength-and-etfs`가 같은 예약 시각에
독립 실행되어 별도 보강 메시지를 같은 신고가 채팅방으로 보낸다. 대규모 일봉
수집 때문에 추가 알림이 더 늦게 올 수 있다. GitHub 예약 시각은 전송 시각이 아니다.

- 실행: `python -m pipeline.strength --market kr --dry-run` (전송·파일 저장 없음).
  실제 전송은 `--dry-run`을 빼고 실행한다. 수동 Actions의 기본값은 dry-run이다.
- 비교 범위: 기존 신고가 스크리너의 유형·시총·당일 거래대금 필터는 유지하되,
  하락 종목도 포함한다. 수집 상한 8,000행이며 **전 상장종목 순위가 아니다**.
  당일 거래대금 필터와 다운로드 성공률에 따라 비교 모수가 바뀔 수 있다.
  시장별 종합 점수 모수와 수집 성공 수를 메시지에 명시한다.
- KOSPI 종목은 KOSPI, KOSDAQ 종목은 KOSDAQ. Yahoo에서 실제로 가격이 조회된
  `.KS`/`.KQ`로 구분한다. 미국은 S&P500 공통, 일본은 TOPIX ETF 1306 대용이며
  ETF 추적오차·분배금 등으로 TOPIX 원지수와 일치하지 않는다.
- 종합 raw score는 최근 4개 **비중첩** 63거래일 구간의
  `(종목 수정종가 수익배율 / 벤치마크 수정종가 수익배율 - 1)`을
  최근부터 40/20/20/20% 가중한 값이다. 시장별 유효 종목을 동률 평균순위로
  1~99 정규화한다. 단일 종목은 순위 미산출. IBD/깡토 공식 점수가 아니다.
- RS 1/3/6M은 21/63/126거래일 상대 수익배율의 독립 백분위이다.
  기간별 유효 모수는 JSON의 `rs1_n/rs3_n/rs6_n`에 저장한다. 253개 세션이 없는
  신규 상장은 종합 RS·MTT를 미산출하고 가능한 단기 점수만 표시한다.
- RS 가속/둔화는 1M 점수와 종합 점수 비교이며 같으면 `동일`이다.
  RS선 신고가는 당일 포함 63일 최고치 (기존 고점과 동률 포함).
- 벤치마크 거래일에 정렬하고 가격을 forward-fill하지 않는다. 최신 지수일의
  종가가 없는 종목은 제외한다. 수익률은 정확한 기준일의 양 끝 가격을 사용하고 기준일 가격이 없으면 미산출한다.
  이평·MTT·RS선 신고가는 연속 관측치가 필요하므로 구간 내 결측도 허용하지 않는다.
  수정주가에는 배당도 반영될 수 있다. MTT는 제공된 8개 조건을 적용하며,
  고가·저가도 동일한 수정비율을 사용한다. RS 점수 70 이상이 8번째 조건이다.
- 상대강도 상위: 종합 RS≥90이고 최근 1M 시장 대비 성과가 양수인 종목.
- 거래대금: 실제 체결금액 합계가 아닌 **원종가×거래량 추정치**.
  오늘을 뺀 직전 20일 평균의 2배 이상 또는 직전 20일 최고치 초과.
  가격 급등·분할일에 해석이 왜곡될 수 있다. 0거래량·결측 기준일은 미산출.
- R/S Flip은 상대강도가 아닌 Resistance→Support이다. 20~126거래일 전 고점을
  앞뒤 5개 봉으로 확정하고, 확정 이후 0.5% 초과 종가 돌파가 먼저 있어야 한다.
  돌파 후 20일 이내 첫 ±3% 저점 재접촉에서 종가가 저항 위이고 전일보다 상승한
  경우에만 표시한다. 중간 종가 이탈 또는 이전 재접촉이 있으면 제외한다.
  이는 예시 사진을 참고한 자체 조건이며 해당 채널과 같은 신호를 보장하지 않는다.
- ETF는 `config.STRENGTH_ETFS`의 기존 주간 주요 지수·업종 ETF 목록과 미국
  VTI/IWM/TLT/GLD를 사용한다. 주식 RS와 섞지 않고 ETF끼리 따로 순위를 매긴다.
  해외자산·채권·금 ETF도 **상장국 주가지수 대비**이므로 동일 자산군 내 순위와 다르다.
  ETF에는 별도로 상승·양봉 마감 + 직전 252거래일 대비 장중 52주 신고가도 표시한다.
- 종목별 상세는 `docs/data/<시장>/strength.json`, `strength_etf.json`에 저장한다.
  각 조건 상위 15종목을 메시지에 표시한다. 가격과 지수가 모두 오래된 경우에도
  기준일이 그대로 표시되므로 최신성은 기준일을 확인한다.
- 중복 방지는 주식/ETF 별도로 하며 전송이 모두 성공한 후 상태를 기록한다.
  전송 중 일부만 성공하고 재실행되면 일부 메시지가 중복될 수 있다.

### DART 근거 기반 업종 검토

`DART_API_KEY`는 기존 공시 조회와 같은 Actions secret을 재사용한다. 키 값을 파일이나
로그에 쓰지 않는다. `dart-classification-review` 워크플로는 매주 월요일 05:50 KST에
최대 40개 기업의 기업개황·최신 정기보고서 원문을 수집하며, 수동 실행도 가능하다.
실제 API 인증 성공 여부는 해당 워크플로 실행 결과로 확인한다.

- `python -m pipeline.dart_classify --codes 007660,042700 --dry-run`
- `company.json`의 `induty_code`는 **공식 업종코드 원값**으로만 보관하며,
  자체 세부업종 코드로 오인하거나 임의 번역하지 않는다.
- `list.json`에서 가장 최근 정기보고서(정정 포함)를 찾고 `document.xml` ZIP의
  '사업의 내용'을 추출한다. 후보별 키워드 문맥과 매출 관련 발췌·공시 링크를
  `data/newhigh/classification/<종목코드>.json`에 저장한다.
- 후보는 `needs_review`이며 자동 적용하지 않는다. 키워드가 고객사·경쟁사·신사업을
  설명할 수 있으므로 매출 지배력이나 테마 노출을 확정하지 않는다. 업종 후보 규칙은
  제한적이며, 규칙에 없는 업종은 기업개황·매출 발췌만 수집한다.
- 승인된 분류는 `data/newhigh/taxonomy.csv`에 등록한다. `status=approved`,
  `industry`, `source_url`, `reviewed_on`이 모두 있어야 실제 업종을 덮어쓴다.
  `sector/industry/subindustry/themes`는 별개이며 복수 테마는 `|`로 구분한다.
  보고서 매출 근거를 사람이 확인한 다음에만 approved로 변경한다.
- **알림 묶음 기준 변경:** 승인 업종 → 공급자 FactSet 산업 → 미분류 순서이다.
  기존 `labels.csv`는 출처가 검증되지 않은 테마/분류가 혼재하므로 기본 업종을
  덮어쓰지 않고 `legacy_group` 참고 필드로 보존한다. 규모는 `[소형주]` 별도 태그이다.
- 종목별 classification(섹터·업종·세부업종·테마·출처·검토상태·규모)은 새 신고가
  상세 JSON에 포함한다. 기존 프런트엔드에 모든 필드를 새로 표시하는 변경은 포함하지 않는다.
- 군집은 새 업종 기준으로 집계한다. 이전 테마 기준 기록과 섞이지 않도록 신규 기록에
  `classification_version=business-v1`를 넣고, 과거 군집 누적은 같은 버전만 사용한다.
  따라서 적용 직후 5/20일 누적은 새 기록부터 쌓인다. 과거 사후 성과 기록은 보존한다.

### 토스증권 공식 섹터 연결 (PR #2 확장)

한국·미국의 기본 분류는 **토스의 대/중/소분류와 모든 복수 소속**이다.
복수 소속을 이유로 기존 FactSet 업종으로 되돌리지 않는다. 토스에 없는 종목은
별도 `토스 미등록`으로 표시한다. 공시로 검토한 수동 분류는 토스 미등록일 때만
별도 승인 분류로 사용하며, 토스가 있는 종목의 검토 내용은 보조 근거로 보존한다.
일본은 기존 공급자 분류를 유지한다.

시장 전체는 종목당 한 번 계산한다. 업종별 수익률·breadth·거래대금은 해당 업종의
고유 구성종목으로 계산하므로 복수 소속 종목은 여러 업종에 나타날 수 있다.
업종별 종목 수·거래 몫을 합산해서 시장 전체로 해석하면 안 된다.
주간 요약의 합산 가능한 섹터 기여도는 복수 소속 간 동일 분할하며 이를 화면에 표시한다.

연결 준비:

1. GitHub Actions Secrets에 `TOSS_CLIENT_ID`, `TOSS_CLIENT_SECRET` 등록.
   다른 프로그램과 함께 쓰지 않는 별도 API 클라이언트를 권장한다. 토큰 재발급 시
   같은 client의 기존 토큰이 즉시 무효화되기 때문이다.
2. 토스 WTS 설정 → Open API → 허용 IP에 **실제 실행 환경의 고정 송신 IP** 등록.
   일반 GitHub-hosted runner의 IP는 고정되지 않는다. 등록 가능한 고정 송신 IP가
   있는 Windows 실행기를 등록한다. 현재 workflow는 기본 라벨
   `self-hosted`, `Windows`, `X64`로 PC를 선택한다.
   코드에서 IP 제한을 우회하거나 광범위한 IP를 자동 등록하지 않는다.
3. `toss-sector-sync`를 수동으로 dry_run=true, probe=true로 실행해 연결 확인.
   코드 push만으로 토스 조회는 실행하지 않는다. PR 이벤트에는 비밀 키를 전달하지 않는다. 이 확인은 데이터 저장·텔레그램 전송을 하지 않는다.
4. 연결 확인 후 dry_run=false로 전체 분류를 수집한다. 매일 **21:00 KST**에 자동 실행한다.
   `TOSS_ENABLED=false`로 예약 실행을 중지할 수 있다. PC에 로그인해서 실행기가
   온라인이어야 한다. 오프라인이면 GitHub가 최대 24시간 대기한다.

공식 `Sector` API의 목록·구성 주식·관련 ETF만 GET으로 사용한다. 인증 토큰 교환 외
POST, 계좌 조회·주문 엔드포인트는 사용하지 않으며 코드 allowlist로 차단한다.
인증값·토큰을 파일·로그·저장소에 저장하지 않는다. 분류 캐시는
`data/newhigh/toss/labels.json`이며, 전체 수집이 성공한 뒤에만 원자적으로 교체한다.
14일 이상 오래된 캐시나 부분 조회 결과는 기본 분류로 사용하지 않는다.

```
python -m pipeline.toss_classify --dry-run --max-sectors 3
python -m pipeline.toss_classify
```

https://openapi.tossinvest.com/openapi-docs/latest/openapi.json

### 사이트에 토스 분류 반영

- 수집 성공 후 `apply-toss-to-site`가 GitHub 실행기에서 저장된 캐시만 읽는다.
  이 작업에는 토스 키나 사용자 PC가 필요하지 않다.
- 신고가 페이지와 누적 군집·사후 성과의 업종 라벨을 다시 계산한다.
  저장된 가격·차트·뉴스·공시·종목 수익률은 유지하며 메시지를 보내지 않는다.
- 심리 지도·로테이션·추세·통계는 토스의 대분류와 각 계층의 최하위 소속을 사용한다.
  상세 목록은 복수 소속을 모두 반영하며 시장 전체 수치는 고유 종목으로 유지한다.
- 업종 매핑이 달라지면 저장된 주간 구간도 현재 분류로 다시 계산한다.
  이는 과거 당시의 업종 분류를 복원한 결과가 아니다.
- 신고가 카드에는 분류 출처와 모든 토스 소속 경로를 표시한다.
  일본은 기존 공급자 분류를 유지한다.

### 일본 사업 분류 개선 방향

JPX 17·33업종을 사이트 기본 분류로 쓰던 변경을 철회했다. 일본 지도·추세·신고가
기록은 기존 공급자 업종으로 복구하며, JPX 자동 적용 예약은 중지한다.
JPX 원본은 보조 참고 자료로만 남긴다.

일본의 DART에 해당하는 자료는 금융청 EDINET의 유가증권보고서이다.
사업의 내용·보고 부문·부문별 매출 및 이익을 기업 IR 제품 설명과 함께 검토한다.
기존 분류를 기본으로 두고, 사업 근거가 확인된 종목부터 세부업종을 보강한다.
주사업과 보조 테마를 분리하고, 고객·경쟁사 언급만으로 업종을 바꾸지 않는다.
EDINET API v2 자동 수집에는 발급된 API 키가 필요하다. 키 연결 전에는 공개 IR 자료를 활용한다.
